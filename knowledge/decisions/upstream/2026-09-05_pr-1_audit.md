# Decision: v1 merges to devel as audited, with two audit fixes folded in

> Inherited from the upstream project this port started from. It describes
> the original implementation, not this repository; kept for the reasoning
> behind the shared contracts. See [the port decision](../2026-09-06_linux-port-python-appindicator.md).

## What was decided

The v1 branch (`feature/v1-meter`, 33 commits) merges to `devel` after the
six-agent audit. Two findings were fixed before the PR rather than ticketed:
a `rate_limits` block whose windows are all unusable now yields no usage at
all, so the stored `captured_at` stands instead of advancing and the age
line cannot claim stale numbers are fresh; and a failed temp-file write
cleans up after itself. The installer swaps the app bundle atomically. The
remaining low notes are recorded here and in
[gaps_and_leads](../../synthesis/gaps_and_leads.md), not ticketed, because
none has a trigger that fires on its own.

## Why

The freshness line is the one signal the user has for trusting the two
numbers; a payload with a present but hollow `rate_limits` block was
reachable (the existing decode test already produced that shape) and would
have advanced `captured_at` with no data behind it. The fix is four lines
and a test, cheaper than any ticket. Everything else the audit raised
degrades safely and waits for a real trigger.

## Alternatives considered

- Ticket the HIGH finding and merge first: rejected, the fix is smaller
  than the ticket and the bug lies on the routine path.
- A `deinit` invalidating the app's refresh timer (code-reviewer LOW):
  rejected for now, Swift 6 forbids touching a main-actor property from
  `deinit` without `nonisolated(unsafe)`, and the model lives for the
  process lifetime.
- Reject `resets_at` outside a plausible window so a unit change upstream
  shows dashes instead of a clamped huge countdown (critical-reviewer LOW):
  deferred to gaps_and_leads with the trigger "Claude Code changes the
  `resets_at` unit"; today the probe pins it to epoch seconds.
- Tighten the snapshot directory to 0o700 (security LOW): not needed, the
  file holds two percentages and two timestamps.
